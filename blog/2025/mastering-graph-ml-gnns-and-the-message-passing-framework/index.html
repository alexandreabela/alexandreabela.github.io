Graph neural networks promise to unlock the full power of relational data — but what really happens inside a GNN layer, and why does permutation equivariance matter so much? If you’ve ever used graphs in ML but still treat GNNs as a black box, this is where that stops.

Graph neural networks (GNNs), as their name suggests, are algorithms that work with graphs. Since graphs are a non-linear data structure, these models or algorithms need to account for the specific properties that stem from how graphs are represented mathematically.

Permutation equivariant assumption

As we have already seen in the first article of this series, Introduction to Graph Data, graphs are represented mathematically with the adjacency and feature matrices. In both these matrices, rows represent either the features of a node or its neighbors. To illustrate some specificities that GNNs need to account for, we’ll look at the adjacency matrix of a graph, but the problem remains the same with the feature matrix.

In the adjacency matrix, rows represent the neighbors of a node, so the first row represents the neighbors of node n°1, the second row represents the neighbors of node n°2, and so on.

However, the problem with this representation is that there is no such thing as node n°1 or node n°2 in a graph. The node numbering in a graph is arbitrary, and the following three representations for the same graph are equally valid

Even though several adjacency matrices can be different and represent the same graph, since there is one underlying graph, you want your model to predict the same value for this graph, regardless of which adjacency matrix you choose to represent it. To illustrate a bit, let’s take the example of a fraud detection model on a graph where nodes represent persons and edges represent transactions between them. The model should predict the same node as fraudsters, no matter which node numbering you choose. A fraudster is a fraudster regardless of the fact that it is modeled as node n°1, node n°2, or node n°10 in your graph.

Now, let’s look at the difficulties of building a model that outputs a single prediction for the same graph that can be represented differently as input. This may seem counterintuitive, as other deep learning models typically output different predictions for different input matrices. Hopefully, GNNs do not need to output the same prediction for totally different matrices. The several matrices that represent the same graph are related by permutation, which means that for each adjacency matrix, it is possible to retrieve another adjacency matrix of the same graph with a permutation matrix

Another aspect of working with graphs is that, in some cases, you don’t just need to predict something for whole graphs but also for nodes or edges in a graph. So, GNNs need to be equivariant to these permutations of the adjacency matrix rows, which means that a permutation of the input matrix results in the same permutation being applied to the output. By contrast, a model that is invariant means that a permutation of the input matrix does not change the output. To conclude, GNNs are special algorithms since they are equivariant to the permutations of the adjacency matrix rows of their input graph.

Being equivariant to all the permutations of the adjacency matrix rows of their input graph is a strong constraint on the model, and some researchers (including me) are trying to relax this constraint. For example, by building a model that would be equivariant to some but not all permutations of the adjacency matrix rows of their input graph.

Now that we have introduced a bit about the specificities of GNNs, but also every model that works with adjacency or feature matrices to represent a graph, let’s dive deeper into how GNNs, via the message passing scheme, can build node representations that incorporate features and structural information while remaining equivariant to node permutation.

The message passing framework

The message passing scheme or framework is a way to add structural information to the feature information contained in the feature matrix. While it is relatively simple to understand, it has demonstrated very strong performance on various graph-related tasks, such as node/edge classification, node/edge regression, or graph classification/regression.

So, how does the message passing scheme work? It starts by aggregating all the feature information from a node's neighbors.

Then it passes the neighborhood aggregation result along with the previous node representation into a non-linear update function. Note that this function is an elementwise function, which means that the output vector of this function is a vector of the same size as the input vector, where the function is applied independently to every element of the input vector.

After that, the output of the update function is the new node representation.

Finally, you repeat this process for each node in the graph, and this completes one layer of message passing over your graph.

As you can have already guessed, this framework is quite modular because you can design several aggregation functions, but also different update functions depending on the task you need to solve. We’ll go through three of the most popular variants of this framework in the next section: Graph Convolution Networks (GCNs)[2], Graph Attention Networks (GATs)[3], and GraphSAGE[4].

GraphSAGE[4]

Another approach that, in theory, can generalize more naturally to unseen nodes is GraphSAGE[4]. Rather than assigning a unique embedding to each node, as previous algorithms do, it focuses on training a collection of aggregator functions. These functions are designed to combine feature information from the local neighborhoods of nodes, with each function responsible for aggregating data from varying hop distances. Then, during inference, the model leverages these trained aggregation functions to create embeddings for nodes it has never encountered before.

As described in the paper [4], let’s first outline the forward propagation, i.e., the embedding generation, which assumes the model has already been trained. We’ll see afterwards how the model is trained.

The algorithm of the forward propagation operates by progressively iterating through different hop distances (or levels of search depth). At each step, nodes gather information from their immediate neighbors, and with each subsequent iteration, they gradually accumulate insights from increasingly distant parts of the graph.

At each iteration k, a node v combines the representations of its immediate neighbors into a single vector.

Following this aggregation, GraphSAGE merges the node’s current representation with the aggregated neighborhood vector by concatenating them. The resulting vector is then passed through a fully connected layer with a nonlinear activation function.

To avoid any numerical instabilities, they normalize every node representation at each iteration k

Finally, the final representation output at depth K is the node embedding we’ll keep.

Another interesting idea from the GraphSAGE model is its use of neighborhood sampling. Instead of aggregating features from an entire neighborhood, it selects a fixed-size sample of neighbors through uniform sampling. This approach ensures that the computational cost for each batch remains consistent.

Now that we’ve seen how embeddings are generated at inference time with the GraphSAGE algorithm, let’s explain how the aggregation functions are trained in a fully unsupervised setting to generate meaningful node embeddings.

In the GraphSAGE framework, three candidate aggregation functions were used: mean aggregator, pooling aggregator, and LSTM aggregator.

First, the mean aggregator is almost equivalent to the convolution propagation rule we’ve seen in GCNs

A key difference between the mean aggregator in GraphSAGE and the convolutional aggregator in GCNs is that the mean aggregator skips the concatenation step. In contrast, the convolutional aggregator in GCNs combines the node’s previous layer representation with the aggregated neighborhood vector through concatenation.

Then, in the pooling aggregator approach, each neighbor’s vector is independently fed through a fully connected neural network. Following this transformation, an element-wise max-pooling operation is applied to aggregate information across the neighbor set.

In their ablation studies, the authors did not find a significant difference between max- and mean-pooling. So it seems that the two could be used interchangeably.

Lastly, a more advanced aggregator leverages the LSTM architecture, offering greater expressive power compared to the other aggregators. However, because LSTMs process inputs sequentially, they lack symmetry (i.e., they are not inherently permutation invariant), which is necessary for the overall model to maintain permutation equivariance. To address this, the authors modified LSTMs to handle unordered sets by applying them to a random permutation of the node’s neighbors.

Training aggregator functions rather than individual embeddings allows GraphSAGE to serve as an inductive framework that efficiently utilizes node feature information to generate embeddings for nodes it has not seen during training.

Conclusion

So far, we’ve seen how the message-passing framework works in GNNs. It first aggregates the representation of a node’s neighbors and then passes this aggregation into a non-linear update function that outputs the updated node representation. As a general framework, message-passing GNNs have many variations, of which we have explained three of the most used: GCNs[2], GATs[3], and GraphSAGE[4].

What’s coming next? Even though message-passing GNNs are quite powerful in many applications, they do come with several disadvantages or weaknesses. We’ll cover them in the next article while explaining some of the tricks that can be used to tackle them.
