Ever wondered how social networks recommend friends or how scientists predict molecular properties? The answer lies in graphs — a way to represent data that captures relationships and patterns.

While traditional tabular data falls short in capturing connections, graphs excel by modeling the structure of complex systems. In this series of articles, we’ll break down the basics of graph data and how machine learning leverages it to solve real-world problems. Whether you’re a beginner or just curious, this is your gateway to understanding graph-powered insights.

Introduction to Graph Data

The first step to understanding Graph Machine Learning is to understand graphs. I’ll try to introduce this data structure and how it can be represented. It will be an introduction, and I encourage you to learn more about the mathematics of graph theory.

What is Graph-structured Data?

Graphs are non-linear data structures composed of nodes and edges. Let’s break it down. Nodes are the basic units of a graph, and are connected by edges. To illustrate what I’m saying, I’ll give you an example. Let’s say you have a social network consisting of four people.

Congrats! You have successfully built your first graph. The users of the social network are the nodes, and the links you made between them are edges.

Now, why are graphs considered non-linear data structures, and what are non-linear data structures? To understand non-linear data structures, we must introduce linear data structures. Linear data structures are a type of data structure in computer science where data elements are arranged sequentially or linearly [2].

What does this mean for graphs? Nodes and edges are not arranged sequentially or linearly. Instead, they are arranged in sets, which is why graphs are considered non-linear data structures. You can think of sets as lists where there is no fixed index, a bit like a bag of balls where there is no ordering or numbering since the balls are all freely rolling in the bag. I hope you get the idea, but you must take home that there is no fixed numbering of nodes in a graph: no particular node is more relevant than the others to be labeled as node n°1 or node n°2 or any index you choose. Choosing indices for nodes or edges in the graph is arbitrary.

Why and When to Represent Data as Graphs?

As you may have already understood, graphs model relationships (edges) between objects (or nodes). They are quite powerful in problems where one might want to encode links within the data. Networks are a great example of graph applications, but you could also use graphs for molecules, where atoms are linked by covalent bonds.

Almost every data or problem can be modeled as a graph. Images can be graphs where nodes are pixels, and they share an edge if they are adjacent in the image. Text can be represented as graphs where nodes are words, and they share an edge if they have a semantic link between them. However, the problem is that a graph representation may not be optimal for every type of problem because sometimes representing a linear data structure like an image or a text as a non-linear data structure might come with more problems than solutions. So, you’ll need to be careful when representing your data as a graph that it is indeed the right data structure to use.

How can we Mathematically Represent a Graph?

Formally, a graph is defined by a set of nodes denoted by V and a set of edges E between these nodes.

However, in order to make calculations and especially machine learning on graphs, we need to make a numerical representation of a graph. This is where the adjacency matrix is useful. You may have already noticed, but the ordering we used between the nodes was arbitrary. Indeed, the same graph can be represented by different adjacency matrices depending on which node is node n°1, which node is node n°2, and so on.

We say that the different adjacency matrices of the same graph are related by permutations (rearrangements of rows and columns that correspond to reordering the nodes of the graph). Note that this property is extremely important, especially when designing models that work on graphs. Since the same graph can be represented by different adjacency matrices, a good model should return the same prediction when these different adjacency matrices are used as input. I’ll cover more on this later in the series when I introduce Graph Neural Networks and the message passing framework.

How can We Additionally Encode the Graph Information?

Now that we have mathematically represented graph structures, i.e., the connections between the nodes, we also need to represent the information about each node.

The node features represent this information. They are the numerical representations of the characteristics of each node. For instance, in social networks, the features of a node can be the verification status (whether or not a user has a verified account), age, and time spent on the network per day for the person that is represented by the node. For a molecular graph, it can be the atomic number, atomic mass, number of isotopes, and number of valence electrons.

A way to conveniently imagine feature information is by assigning a vector (a list of numbers) to each node in the graph.

Then, to aggregate all this information into a single object, you can use a matrix by stacking all the feature vectors for each node. This matrix is the feature matrix, and we’ll note it as X.

Two important remarks about this feature matrix. As you might have already noticed, this matrix also depends on the ordering of the nodes, which is arbitrary. Therefore, several feature matrices can represent the information of the same graph. These matrices, as adjacency matrices, are related by permutations. Also, the number of features you use (the size of the vector for each node) is totally up to the problem you’re solving and its design. Hence, the feature matrix size may change depending on what information you decide to keep in your graph.

Are There Other Types of Graphs?

Until now, I have focused on undirected graphs, but many other types of graphs exist, and models have been designed to perform learning on them. I’ll try to present the most popular ones now.

First, let’s talk about weighted, directed, and bipartite graphs, which are the closest to the undirected graphs we have presented so far.

A weighted graph is merely a graph where edges have been assigned weights. For example, a road network graph that uses cities as nodes and routes between them as edges might represent the fact that different routes don’t have the same length or travel time.

A directed graph is simply a graph where edges are directed, meaning that an edge from node 1 to node 2 is not the same as an edge from node 2 to node 1. Indeed, sometimes it can be useful to model the fact that a relationship between two nodes can be unilateral. If you think of a social network graph, being a follower or being followed by someone should not always be treated the same way.

A bipartite graph is a graph (undirected or directed and/or weighted) where the nodes can be divided into two separate categories such that all edges connect nodes present in one set to nodes in another set. For instance, in recommender systems, we could use graphs where users and items are represented as nodes, and there is an edge between the nodes if the user has purchased a particular item.

Other types of graphs change the structure of the graph. We’ll see only multidimensional graphs and hypergraphs, but many others can be used depending on your problem.

A multidimensional graph is a graph where two nodes can be related by more than one edge. Let’s take again a transportation network where cities are represented as nodes and routes between them as edges. Some cities can be connected by plane, train, and car. These connections should not be modeled the same way since their travel time and/or distance vary greatly depending on the mode of transport.

A hypergraph is a graph where one edge can connect more than two nodes. It can be useful when trying to model social network groups as a graph. The users are represented as nodes, and the groups are hyperedges (edges that connect several nodes) connecting several users.

The way to represent these hypergraphs is to use an adjacency matrix where rows represent nodes and columns represent hyperedges. In the example above, since the first column represents group A, nodes n°2, n°3, and n°4 (Julie, Louis, and Léa) are connected by this hyperedge; we put a 1 in positions 2, 3, and 4 in the column and 0 elsewhere.

Graph Machine Learning

Hopefully, now you should have understood the gist of how graph data works. You can already do a lot of analysis by just representing some data as graphs, and you should dive deeper into the mathematics of graph theory if you want to extract more from graph data without machine learning. But now it’s time to see what machine learning and graphs can accomplish when put together!

What can we do when combining graph data and machine learning together?

Since graph data differs a lot from traditional data, graph machine learning comes with its own set of tasks. I’ll try to emphasize the most popular ones, but there are a lot of them, and you should check if there is one that fits your problem.

One particularity of graph machine learning is that its tasks can be divided into 3 categories namely node-related tasks, where you want to predict a target for each node in a graph, edge-related tasks, where (you already guessed it …) you want to predict a target for each edge in a graph, and graph-related tasks, where you try to infer a target from whole graphs.

To my knowledge, the 7 most popular graph machine learning tasks are: node classification and regression, edge prediction, community detection, graph classification, graph regression, and graph clustering.

Node classification is a task where a model predicts a label for each node in the graph. A classic example would be fraud detection, where in a network of transactions (nodes as users and edges as transactions between them), you aim to predict which users are fraudsters.

Node regression

Edge prediction (or link prediction) aims to predict missing or future connections between nodes.

Community detection tries to find groups of nodes in a graph. You can see this task as a clustering problem within a graph. It can be particularly interesting for online targeting when a company tries to target people who are similar to the ones they already know to like their products.

Now I’ll focus on graph-related tasks where the models make predictions on whole graphs rather than on nodes or edges.

First, graph classification is quite straightforward. We ask the model to label different graphs. It is especially useful for biomedical applications. For instance, PROTEINS[5], a well-known dataset, represents proteins as graphs, and the goal is to classify them as enzymes or non-enzymes.

Graph regression is similar to other types of regression, but it works on graphs. Hence, the goal is to assign a scalar value (a number, basically) to a graph. Again, it is useful in biomedical applications when one might want to predict the toxicity as a number of a molecule that is represented as a graph.

Graph clustering is also similar to other types of clustering algorithms, but unlike community detection, it works on whole graphs. It can be useful when trying to find similar molecules that could interact well with each other.

Why Graph Machine Learning and not just traditional Deep Learning on graphs?

All of the tasks presented before are solved under consideration of both the adjacency and feature matrix. You could rightly wonder why we are trying to propose and build new methods specifically for graphs, whereas traditional machine learning and deep learning methods work well with matrices and could use the adjacency and feature matrix as inputs.

One problem with this idea is that traditional machine learning and deep learning methods have the identically and independently distributed assumption on data. What does that mean? As simply explained in [4], identically distributed means that every datapoint comes from the same distribution, i.e., if you take any large enough sample of your data, the mean and the variance should be the same.

For example, if you want to detect fraud in transaction networks (modeled as a graph or not), it means that the samples of the first 1000 transactions or the last 1000 transactions should approximately have the same mean and variance amount (or any sample of 1000 transactions). Note that the number 1000 transactions is arbitrary; I just wanted to show that this property arises with “large enough” samples. The identically distributed assumption stands with graph data since it has nothing to do with the structure of the graph, but rather the node features.

However, the independently distributed assumption does not hold when using graph data. Indeed, independently distributed means that there is no influence between datapoints, i.e., the outcome of one datapoint provides no information on the outcome of another datapoint.

For instance, if you want to predict the price of houses based on different features like surface, number of rooms, location … This assumption means that the prices of one house will not influence the price of other houses; it will only depend on the features of these houses. When using graph data, we are instead modeling an interconnected set of nodes and edges where we want the features of one node’s neighbors to influence the node prediction. Therefore, the independently distributed assumption of traditional machine learning and deep learning methods does not hold, and we need specific models to deal with graphs.

How can we account for graphs in machine learning?

When developing models, the graph machine learning community has come to exploit 3 main ideas to account for the specific type of data that is graphs: homophily, heterophily, and structural equivalence.

First, homophily is the tendency for nodes to share the same label as their neighbors. In the case of node classification, in a homophilic graph, nodes will tend to have the same target class as their neighbors.

Then, heterophily is the opposite. It’s the tendency for nodes to be preferentially connected to nodes with different labels. In the case of node classification, in a heterophilic graph, nodes will tend to have a different target class compared to those of their neighbors.

Finally, structural equivalence is the idea that nodes with similar local neighborhood structures will have similar labels. For instance, in node classification, that can mean that nodes with the same label can have the same degree (number of neighbors) or any measure on the neighborhood structure.

We’ll see in the article covering Graph Neural Networks how models attempt to leverage these three ideas to obtain good performances on graph machine learning tasks.
