Embeddings are crucial in machine learning models, as they provide a good way to represent complex data structures in compact vector representations. Graph data is no exception to this, and here’s how you build node embeddings.

What are node embeddings?

As in other domains of machine learning or representational learning, embeddings are representations of objects in a latent space that we choose, where geometric relations correspond to relationships between objects in the original space. Hence, node embeddings are representations of nodes in a latent space (usually as a vector of real numbers), where geometric relations correspond to relationships, such as edges, in the original graph.

For instance, let’s say we have the following graph, and we want to represent the three nodes u, v, and w with one number (1D embedding).

Since u and v are connected in the graph, their representation should be closer in the embedding space than with the representations of node w. For 1D embedding, this means that the distance between the numbers by which we choose to represent them should be less than the distance between the representations of node u and node w, as well as the representations of node v and node w.

The same idea holds when you increase the dimension of your embedding space. For example, if we choose to represent nodes with two real numbers, then the distance in R² between node representations should verify the same properties as with a 1-dimensional embedding space.

Again, the same property is true for higher-dimensional embeddings. Usually, node embeddings have a higher dimension since representing nodes with only two numbers does not account for the complexity of their relationship with other nodes in the original graph.

Note that node embeddings are different from node features, which we’ll get to in the next section on Deep Learning Methods. Node features are not used in these methods, and the node embeddings try to represent only the structural information of the graph for each node.

Encoder-decoder approaches

The first approach to building node embeddings is the encoder-decoder approach. As the name suggests, it involves an encoder that takes as input the adjacency matrix of the graph and outputs node embedding vectors. However, the encoder still needs a training task to optimize the node embeddings; this is where the decoder part is useful.

The decoder will take the node embeddings as input and will try to reconstruct graph statistics from them. The standard approach is to define a pairwise decoder that predicts the similarity score between pairs of nodes.

The similarity score matrix S is derived from the adjacency matrix A, but it might also be adjusted to include additional information. For instance, if u and v are neighbors in the graph, then S[u,v] = 1, but S[u,v] = 0.5 if they share a common neighbor even though they are not directly connected.

Matrix-factorization approaches

Another way of building node embeddings is by viewing this task as using matrix factorization to learn a low-dimensional approximation of the pairwise similarity matrix S.

I’m not particularly familiar with these methods, but I still wanted to highlight this interesting way of thinking about node embeddings. If you want to learn more about these approaches, you should check the most popular methods: graph factorization[7], GraRep[8], and HOPE[9].

Random walk approaches

The final way of building node embeddings that we’ll explore is using random walks. The idea with random walks embeddings is that two nodes have similar embeddings if they tend to co-occur on short random walks over the graph. One benefit of the random walk approaches is that they can be extended and modified by biasing or modifying the random walks. For instance, you could give higher probabilities of occurring in the random walk to the nodes you’ve already visited, or the other way around.

So, when you have node sequences from random walks, how can you build node embeddings from them? Random walks node embeddings algorithms use a similar architecture to the one used to get word embeddings using the word2vec skip-gram method[2], where the goal is to predict the words that will be in the context of a target word. Hence, I’ll start by explaining this method from natural language processing.

With words, you’ll use a sliding window that looks at the words before and after the target word to get the sequence of training samples. If you use a sliding window of size 5, you’ll build your training examples from the French simple sentence “Le chien est dans la maison” as follows.

After getting these training sequences, in the word2vec skip-gram model, both the input vector and the output are one-hot encoded word representations. This means that for every word in the dictionary, you create a vector with a one value and zeros everywhere else. The position in the vector where you put the one value is unique to every word, so you could have something like the first word of the dictionary has a one at position 1 and zeros everywhere else, and the second word of the dictionary has a one at position 2 and zeros everywhere else, and so on.

The word2vec skip-gram model[2] is then a neural network with one hidden layer and an input layer and an output layer of the same size corresponding to the size of the vocabulary, since the input and output vectors are one-hot encoded. In this model, after training, the weights of the model will represent all the word representations.

Now, how can we translate into getting node embeddings? First, we need to build a training dataset with node sequences that will have the same role as sentences in the word2vec skip-gram model[2]. Then, we’ll build training samples in the same way as before, with (target word, context word), but in the case of node embeddings, tuples (target node, context node) will be built using a sliding window on the node sequences.

The two most used methods to generate random walk embeddings, DeepWalk[4] and node2vec[5], differ in how they define the training node sequences. Based on the explanations in [6], let’s analyse both of them.

First, DeepWalk[4] uses random walks to generate several node sequences starting from each node in the graph. To generate these training node sequences, it starts from a node and uniformly samples the next node from the neighbors of the current node. This means that for a specific node, all neighbors have the same probability of being visited at the next step of the random walk.

Let’s take the same graph as before and start the node sequences from node 1.

All neighbors of node 1 (here, 3 and 4) will have the same probability of being visited at the next step of the random walk.

Then, let’s assume the random walk goes to node 3. Again, all neighbors of node 3 (here, 1, 2, 4, and 5) will have the same probability of being visited at the next step of the random walk.

This iteration continues until it reaches the desired random walk length.

Similarly, the node2vec algorithm also uses random walks to generate several node sequences starting from each node in the graph. The difference with node2vec[5] compared to DeepWalk[4] is that the algorithm generates node sequences using second-order walks that take into account both the current as well as the previous state.

Let’s see how it changes the node sequences that we build for our training dataset, and start with the same graph as before, from node 1.

At the first step, since the random walk did not visit any node at the previous step (since there is no previous step), the node neighbors' probabilities of getting visited remain the same as with DeepWalk[4].

Then, let’s assume the random walk goes to node 3. This is where node2vec[5] and DeepWalk[4] differ. node2vec[5] allows taking into account nodes that have been visited before, but also nodes that are not neighbors with nodes previously visited. To do so, we assign a weight 1/p to nodes that have been visited before and a weight 1/q to nodes that are not neighbors with nodes previously visited in the random walk.

The values p and q are chosen as hyperparameters of the model, and they influence how the random walks visit the graph.

First, choosing a low value for p (p<1) encourages the random walk to stay close to the starting node. On the contrary, setting a high value for p (p>1) encourages more exploration within the graph.

Then, q also influences how the random walks go through the graph. Setting a low value of q (q<1) encourages the model to visit nodes further away from the starting node, which corresponds to an approximation of a depth-first search in the graph. Conversely, choosing a high value of q (q>1) biases the random walks to visit nodes close to the node in the previous step, which corresponds to an approximation of a breadth-first search in the graph.

Drawbacks of traditional node embeddings

Even though traditional node embeddings are quite powerful tools to build a node representation that takes into account the structural information induced by the graph data structure, they are not perfect and come with some disadvantages.

First, these node embeddings can be quite computationally expensive and not well optimized. Indeed, these embedding methods do not share any parameters between nodes in the model or encoder, since they directly optimize a unique embedding vector for each node.

Also, they are inherently transductive, meaning that these methods can only generate embeddings for nodes that were present during the training phase, which can be harmful for some applications with regularly changing graphs, like social networks or molecules in a chemical reaction. Besides, and perhaps more importantly, these methods do not leverage node features but only the structural information.

That will motivate new methods to get node representations without these drawbacks. We’ll see about them in the next section on Deep Learning Methods.

Conclusion

This article concludes the section on Traditional approaches to machine learning on graphs. So far, we’ve seen how we can construct features or statistics from the structural information embedded in the graph data structure. However, these methods were not perfect and especially since they did not use the features or attributes that nodes or edges can have. Deep Learning methods on graphs are an attempt to leverage both structural information from the graph and the feature information.
