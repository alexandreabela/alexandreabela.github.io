Before delving deeper into understanding graph machine learning and graph neural networks (GNNs), in my opinion, it is necessary to understand the traditional approaches used in machine learning with graph data, which paved the way for the graph machine learning models we use today.

Traditional approaches in graph ML

Traditional approaches to machine learning using graph data begin by extracting some statistics or features, based on heuristic functions or domain knowledge, and then use these features/statistics as input to a standard machine learning model.

As graphs involve two types of objects, namely nodes and edges, there are often three categories of features that are usually used in traditional approaches: node statistics, edge statistics, and graph statistics. I’ll try to make sense to you of the most popular ones in each category in this article.

Node statistics

At the node level, the four main statistics used in traditional methods in machine learning using graph data are: node degree, eigenvector centrality, betweenness centrality, and local clustering coefficient.

The degree of a node is the number of neighbors one node has. Recall that at this stage, we have already represented the graph with the adjacency and features matrices. Therefore, how can we compute the node degree from these matrices? It is computed by summing over the rows of the adjacency matrix :

Remember how we built the adjacency matrix, we first filled row n°1 and put a 1 in the position corresponding to node n°1's neighbors, then we did the same for every other node in the graph.

Hence, summing over the rows in an undirected and unweighted graph gives the number of neighbors. On the contrary, in a directed graph, the scientific literature makes a distinction between the in-degree, meaning the degree corresponding to incoming edges, and the out-degree, meaning the degree regarding outgoing edges.

The eigenvector centrality measures the importance of a node in a network by considering not just the number of its connections, but also the importance of the nodes it is connected to. Unlike other centrality measures like the node degree, the eigenvector centrality doesn’t just look at the number of connections a node has — it also considers how important the connected nodes are. In other words, being connected to influential nodes increases your influence. Think of it like this: In a social network, being friends with a few highly popular people (like celebrities) might make you more “central” than being friends with a large number of less influential people.

To calculate eigenvector centrality, we use a mathematical concept called an eigenvector. It is a special kind of vector used in linear algebra. When you multiply a matrix by an eigenvector, the result is the same eigenvector scaled by a constant (called the eigenvalue).

In simple terms, the eigenvector tells us how influence or importance is distributed across the nodes in the network.

To compute the eigenvector centrality, we start with an initial guess for the scores (i.e., all nodes have equal scores). Then, we repeatedly update each node’s score to be proportional to the sum of the scores of its neighbors. This process continues until the scores stabilize, which corresponds to finding the eigenvector of the adjacency matrix.

The eigenvector centrality is quite a powerful tool, as PageRank, the algorithm that ranks pages in the Google search engine, is a variant of the eigenvector centrality.

On the other hand, betweenness centrality measures how important a node is in terms of connecting other nodes in the network. Specifically, it quantifies how often a node lies on the shortest paths (or geodesics for geometrical nerds) between pairs of other nodes. In simple terms, a node with high betweenness centrality acts like a “bridge” in the network, helping to connect different parts of the graph. It’s particularly useful for identifying nodes that control the flow of information or resources in a network.

Now that you got that, the idea behind betweenness centrality is to count how many of the shortest paths between all pairs of nodes pass through a given node. Let’s see how it is computed. First, for every pair of nodes in the network, find all the shortest paths between them. Then, for each node, count how many of these shortest paths pass through it. If a node lies on many shortest paths, it has a high betweenness score.

It can be especially useful in transportation networks to find critical roads, airports, or train stations that connect regions.

Finally, the local clustering coefficient measures how tightly connected the neighbors of a node are or how close the neighborhood of a node is compared to a complete graph (a graph where all nodes are connected). If you think of a social network, the clustering coefficient measures how many of your friends are also friends with each other.

How can you compare one node neighborhood to a complete graph? Since having a high clustering coefficient would mean that one node's neighbors are connected to other neighbors of the same node, one could suggest counting the number of edges between neighboring nodes. It would be a start, but this measure would be biased towards nodes with a high degree. Indeed, a node with 3 neighbors connected together only has 3 edges between neighboring nodes will have a lower clustering coefficient than a node with 50 neighbors and 5 edges between them. Hence, we need to normalize by the number of possible edges between neighboring nodes. For that, we can take the number of possible pairs of nodes in a node neighborhood. For instance, in social networks, it can measure how tightly-knit groups or communities are, and in biological networks, it can help identify clusters of highly interacting entities, like proteins or genes.

Edge statistics

Now that we’ve seen several ways to get statistics on nodes, it might be time to also get statistics on what connects them. The goal with edge statistics is to design features that capture the structure of edges in the graph to use in a traditional machine learning algorithm to predict new edges based on existing ones.

At the edge-level, to my knowledge, the three main edge statistics are: distance-based features, local, and global neighborhood overlap measures.

The most basic method to get edge-level statistics is to use distance-based features, which calculate the shortest path between two nodes. You can compute the shortest path between two nodes using a well-known algorithm like Dijkstra [2], A* [3], Breadth-First Search [4], or any other shortest-path finder algorithm. I won’t cover them in this series, but feel free to learn about them in the resources I’ve put in the references.

Sometimes, using only distance-based features is not enough, and we want to quantify the relationship between a pair of nodes. This is where statistical measures of neighborhood overlap are useful. They can be divided into two categories: local for pairs of nodes that have a two-hop distance between them, and global, which attempt to take relationships beyond the local node neighborhood into account.

The simplest neighborhood overlap counts the number of neighbors that two nodes share

However, this formula is biased towards nodes with a degree. Indeed, let’s say we want to get the statistics on two pairs of nodes (node n°1, node n°2) and (node n°2, node n°3). If node n°1 has 25 neighbors, of which 3 are also connected to node n°2, and node n°3 has 2 neighbors, all of them common with node n°2. The statistics will be higher for the pair (node n°1, node n°2), even though, regarding their whole neighborhoods, node n°3 seems to be more related to node n°2. Therefore, it can be useful to use normalization on this measure

One problem with local neighborhood overlap measures is that they are useless with nodes that do not have a two-hop distance between them. Therefore, we need features that take the relationship beyond the local node neighborhood into account. Global neighborhood overlap measures attempt to do so.

Before throwing at you the Katz index formula (one of the most popular global neighborhood overlap measures), I need to discuss the interesting properties of the powers of the adjacency matrix. Here, I refer to the power of a matrix as the multiplication by itself and not some kind of superpower. You can see the nth power of the adjacency matrix as the matrix that counts the number of paths of length n between a pair of nodes.

So let’s start with the adjacency matrix A. A path of length 1 is just an edge, so the adjacency matrix can be interpreted as a matrix that counts the number of paths of length 1 (edges) between nodes.

Then, what happens when we multiply A by itself? Then, you get the matrix that counts the number of all paths of length 2 between nodes. Feel free to prove it mathematically; it’s not that hard [5], but I won’t do it here; I’ll just show an illustration.

The same happens if you multiply one more time A² by A to get A³.

I’ll stop here because I think you got it. But what do the powers of the adjacency matrix have to do with the Katz index? Well, the Katz index counts the number of paths of all lengths between a pair of nodes by using the powers of the adjacency matrix. It also weights them to give lower importance to paths of high length.

As such, we’re able to compute meaningful statistics even between nodes that do not have a two-hop distance between them. Since the sum goes to infinity, we will find a path between any two nodes, and the longer this path, the lower the Katz index will be because of the constant β.

Graph statistics

Graph kernel methods are a class of techniques in machine learning used to compare and analyze graphs. A graph kernel is a function that computes the similarity between two graphs.

The key idea in graph kernels is to define a feature vector ϕ(G) that can differentiate between two different graphs.

These high-dimensional feature vectors can then be used to represent entire graphs rather than individual nodes or edges and to compute the graph kernel (the measure of similarity between graphs).

It might seem a bit abstract for now, but let’s use an example to illustrate what does graph kernel means. The simplest approach to defining a graph-level feature is just to aggregate node-level statistics, which is known as bag-of-nodes. For instance, you could just choose to aggregate node degrees.

However, bag-of-nodes is entirely based upon local node-level information and therefore can miss important global properties in the graph.

That’s why iterative neighborhood aggregation approaches want to extract node-level features that contain more information than just their local ego graph, as in bag-of-nodes methods, and then to aggregate these richer features into a graph-level representation.

The most used approach is to use features from the Weisfeiler-Lehman (WL) test. It is extremely important because one of the most influential graph ML papers [6] has demonstrated that GNNs within the MPNN framework are at best as powerful as this test to distinguish between two graphs. But I’ll cover that in later articles.

So, how does the WL test work? It works in several steps: one initialisation step, a repeated process of two steps, and a final step to retrieve the feature vector. Then, you just need to compare the feature vectors: if they are equal, then, according to the test, the two graphs are the same.
